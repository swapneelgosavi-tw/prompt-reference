# Pre-Established BIAN Architecture Standards (Already Decided)
Incorporate all of the following architectural rules into the skill you generate:

1. **Target Standard:** BIAN Service Landscape **v14.0** (258 rationalized Service Domains, ISO 20022-aligned data structures, and current domain naming such as `Payment Order Initiation` and `Payment Rail`).
2. **Core Metamodel Mapping:**
   - **Service Domain (SD):** Map each capability to its single, non-overlapping asset-owning Service Domain.
   - **Control Record (CR):** Identify the focal aggregate entity / lifecycle binder governed by that Service Domain (e.g., `CurrentAccountFacility`, `PaymentOrderProcedure`).
   - **Behavior Qualifier (BQ):** Identify sub-aspects or operational facets under the Control Record when the API performs a sub-function rather than managing the whole entity lifecycle (e.g., `DepositsAndWithdrawals`, `AccountLien`, `ComplianceCheck`).
   - **Action Terms:** Replace custom verbs with canonical BIAN Action Terms (`Initiate`, `Retrieve`, `Update`, `Execute`, `Control`, `Request`, `Evaluate`, `Notify`).
3. **Multi-Domain Decomposition (Inner vs. Outer APIs):**
   - **Single-domain endpoint:** Perform a **1-to-1 conversion** into a BIAN Inner API.
   - **Multi-domain endpoint:** Never force multiple Service Domains into one BIAN API. Split the endpoint into separate, fine-grained **BIAN Inner APIs** (one per Service Domain) and document the original endpoint as an **Outer / Experience API** that orchestrates those Inner APIs in sequence.
4. **URI & REST Conventions:**
   - Use kebab-case URIs following the structure:
     `/bian/v1/{service-domain}/{control-record}[/{cr-id}][/{behavior-qualifier}[/{bq-id}]]/{action-noun}`
     *(where `{action-noun}` is `initiation`, `retrieval`, `update`, `execution`, `control`, etc.)*
   - Map HTTP methods cleanly (`POST` for initiation/execution, `GET` for retrieval, `PUT`/`PATCH` for update/control).
5. **Payload, Headers & Error Standards:**
   - **Casing & Naming:** Use **`camelCase`** for all JSON properties, mapping proprietary field names (e.g., `cust_id`, `acct_no`, `amt`) to canonical BIAN Business Object Model (BOM) and ISO 20022 names (e.g., `partyReference`, `accountIdentification`, `instructedAmount`, `currency`, `settlementDate`).
   - **Separation of Metadata:** Move technical/tracing fields (`X-Request-ID`, `X-Correlation-ID`, `Idempotency-Key`) out of JSON payloads and into standard HTTP headers.
   - **Error Responses:** Standardize error definitions using **RFC 9457 (`application/problem+json`)**.
